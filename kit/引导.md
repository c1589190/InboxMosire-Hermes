# 引导文件：把 Hermes 挂到 InboxMosire 上

这个目录里放好 **jar** 和这份文件就够了。打开 `hermes` 之后，直接把下面这句话丢给它：

> 读当前目录的 引导.md，把 inbox 接上，好了告诉我。

Agent 应该做的事（按顺序，失败就停下来说明原因）：

1. `./kit.sh doctor`——看看 java / jar / hermes / 端口 / 插件 / gateway 哪些不就绪。
2. `./kit.sh up`——起 InboxMosire（API `127.0.0.1:18765` + MCP `127.0.0.1:18766/mcp`），
   缺 token 时自动 issue 并写进 0600 文件，挂两个 MCP、写插件设置、必要时重启 gateway。
3. `./kit.sh status`——确认：服务在跑、token 权限 0600、插件 enabled、`mcp_servers` 有 `inbox`。
4. 用一句话向用户汇报结果 + 已知限制（见文末）。

**红线**：`kit.sh` 打印的东西里不能出现 token 明文；如果看到，别复述、别贴进对话。
不要 `cat` token 文件；不要把它写进任何日志或提交。

## 之后怎么用

- 新开会话，直接说需求即可：`autoBind=1` 时首轮会自动绑定，不用打 `/inbox bind`。
- 手动核对：`/inbox status`、`/inbox log`；重连：`/inbox retry`；解绑：`/inbox unbind`。
- 停服务：`./kit.sh down`（只停 kit 起的进程）。

## 已知限制

- 插件跑在 **gateway 进程**里：改插件代码或 `plugins.entries.*` 设置后要 `hermes gateway restart`（`kit.sh up` 会自动判断）。
- `inbox_claim` / `inbox_complete` 需要「程序 MCP」已挂载（`mcp_servers.inbox`）且 token 带 `items:manage`。
- `autoBind` 失败不会打断对话，只会记一条 warning 并保持未绑定状态；此时用 `/inbox bind` 手动绑。
- 本机日志/`plugin-data` 目录权限由 Hermes 宿主决定，插件不改它们（验收 F6 记为未达标）。
